# Обновление голоса после ручного монтажа

Сначала сохранить текущий проект из режима режиссёра. `sync_voice.py --manifest` читает именно этот Markdown и готовит только отсутствующие/устаревшие реплики с их текущим текстом и SHA-256; существующая запись старого текста не помечается пригодной. Подготовленный манифест можно передать существующему генератору через его штатный `media/interactive/chronicles/voice-manifest.json` — это отдельное явное действие, сам sync ничего не отправляет в сеть. После записи `sync_voice.py --apply-cache` подхватывает совпадающие текст, рецепт и файл, обновляет только метаданные голоса, длительности его клипов и выравнивание, сохраняя ручные сцены, музыку, титры, скриншоты, ветки и речь. Результат по умолчанию — новый соседний `.md`, который импортируется в редактор и сохраняется его обычным способом; исходный мастер CLI никогда не перезаписывает. Отчёт показывает наложения голосов и словесные привязки для проверки. Только явный `--ripple` переносит последующие фиксированные точки в той же сцене на изменение длительности; относительные привязки и ручные обрезки сохраняются. Повторно запускать первоначальный `import_project.py` после ручного монтажа не нужно.

```powershell
# Без сети; по умолчанию создаются новые файлы с отметкой времени.
python tools/chronicles/sync_voice.py --manifest
python tools/chronicles/sync_voice.py --apply-cache

# Явное обновление рабочего манифеста для существующего генератора.
# Прежний вывод сохраняется в scratch/chronicles-voice-sync-history.
python tools/chronicles/sync_voice.py --manifest --output media/interactive/chronicles/voice-manifest.json --overwrite

# При необходимости сдвинуть последующий монтаж после новой озвучки.
python tools/chronicles/sync_voice.py --apply-cache --ripple --output scratch/chronicles-with-new-voice.md
```

Оба режима принимают `--master` и `--cache`. JSON-конфиг рассматривается как данные; код из сценария не исполняется. Отсутствующее выравнивание не заменяется приблизительными секундами. При блокировке файла Windows запись повторяется, а полностью подготовленный временный файл сохраняется при окончательном отказе.
